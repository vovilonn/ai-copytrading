# LOOP_STATE

## Goal: «последнее сообщение не нашёл символ, там же очевидно по контексту что это XRP — исправь и зайди по текущим»

Сообщение 221679 (08.09.2026 11:27): «Ещё раз с текущих», реплай в ветку по XRP.
Ушло в `needs_review(symbol_unknown_needs_vision)` — вход потерян целиком.

## Что было

Модель поняла ВСЁ, кроме монеты, и честно об этом сказала:

    add UNKNOWN long, entry={mode:market, marker:current_price}
    summary: "Add to existing long (parent thread symbol) at current market price"

«parent thread symbol» — она искала символ в ветке и не нашла. Ветка:

    «Ещё раз с текущих»  →  «Стоп на твх / Первый тэйк - 1.414»  →  «Xrp long с текущих»

Первое и второе сообщения тикера не содержат, а третье цепочкой реплаев НЕ достаётся (родитель
второго — корень топика). Символ второго сообщения (XRPUSDT) движок в своё время вычитал СО
СКРИНШОТА и исполнил по нему стоп в бу и тейк 1.414 — то есть знал ответ, но никому его не сказал.

## Три причины, все наши

1. **Символ ветки искался ТОЛЬКО в текстах предков.** Второй источник — то, чем предок для движка
   уже оказался (`actions.symbol`), — не использовался вовсе. Это не догадка, а наш собственный
   разобранный результат, и он сильнее любой эвристики по открытым позициям.
   `context.ts::loadReplyChain` теперь тянет и разобранные символы, `resolveChainSymbol` берёт их,
   когда текст предка молчит. Несколько разных символов у предка → подсказки нет (как и с текстом).
2. **`replyChainSymbol` едет в промпт, но не входил в ключ кэша.** Из `replyParentId` он не следует:
   движок узнаёт его позже самого родителя. Перезапуск сообщения после того, как ветка стала
   понятна, честно доставал бы из кэша прежний `symbol=UNKNOWN`. Добавлен в `cacheKey`.
3. **`add` по символу без позиции скипался, даже когда сказано «с текущих».** Нашу позицию по XRP
   выбило в безубытке за 17 минут до сообщения, автор входит заново — для нас это ВХОД. «С текущих»
   — цена, названная словом: догонять нечего, автор берёт по той же живой цене, что и мы.
   `handleAdd` без позиции: цена → лимитный вход (было), «с текущих» → вход по рынку (стало),
   ни того ни другого → по-прежнему `no_open_position`. Ровно то же правило, по которому
   детерминированный CH2 (`tryEntries`) отличает добор от входа по свободному символу.
