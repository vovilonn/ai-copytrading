# LOOP_STATE

## Goal: сообщение потеряло две цели по битку — и это не первый случай в тот день

Заказчик: «последнее сообщение в aacademy потеряло два тейка по битку, поставился только по эфиру.
Пофикси, доставь тейки и сделай правки, чтобы сообщения обрабатывались корректно. Почему AI не
подтянул эти тейки? косяк».

## Что нашлось (канал 1962583820, 23.08.2026)

Потерь оказалось три, в двух сообщениях подряд, и обе разобраны БЕЗ модели (`method=auto`):

    msg 221615  По эфиру первая цель - 2435 стоп на твх
                По битку - 77500
                → выполнен ТОЛЬКО стоп по эфиру

    msg 221618  Третья цель Eth 2520
                По битку первая 🎯
                Следующие - 78800, 79900
                → выполнена ТОЛЬКО цель по эфиру

**Почему модель «не подтянула»:** её не вызывали. Правило D возвращает `route=execute`, если хоть
одна строка разобралась, а при `execute` пайплайн к модели не обращается вовсе. Сообщение
считалось понятым.

**Отдельно:** msg 221617 («Фикс как вторую цель половину от остатка / Eth») ушёл в модель — и
получил 401: у ai-прокси **истёк OAuth-токен**. Сообщение висит в `needs_review`, действий ноль.
Токен протух сегодня: до 22.08 все вызовы проходили, 23.08 — все четыре с ошибкой.

## Причины потерь

| строка | почему пропала |
|---|---|
| «первая цель - 2435» (вместе со стопом) | строка отдавала ПЕРВЫЙ подошедший op: стоп победил цель |
| «По битку - 77500» | нет гейт-слова: вид инструкции подразумевается из предыдущей строки |
| «По битку первая 🎯» | 🎯 не был маркером цели |
| «Следующие - 78800, 79900» | ни гейт-слова, ни монеты — эллипсис по обоим измерениям |

## Фикс (правило D, ch2.adapter.ts)

1. **Строка отдаёт ВСЕ свои инструкции**, а не первую подошедшую. Цена, съеденная стопом, в цели
   больше не уезжает («цель 2435, стоп 2300»).
2. **Строка-продолжение наследует символ И вид инструкции** предыдущей строки. Условие жёсткое:
   только монета, числа, порядковые слова и предлоги — «Биток пока подошёл к 64000 и замер»
   продолжением не считается.
3. **🎯 — маркер цели**, причём ВЗЯТОЙ (`tp_hit`), если новой цены в строке нет. «Следующие» —
   маркер новых целей.
4. **Одна дельта на символ**: ops сливаются, цели одного символа — в одну лесенку. Иначе вторая
   цель того же символа не пережила бы дедупликацию действий по (сообщение, тип, символ).

Плюс две страховки:

- строка выглядит инструкцией (торговое слово + число), но шаблон её не понял, а другие понял →
  сообщение целиком уходит в модель (`partial_parse`), понятые интенты едут с собой;
- **reply-ветка** больше не сужает разбор до одного стопа первой строки: «Стоп на твх, первый
  таргет 73.5» в ответе на сигнал терял цель (нашёл фоновый разбор).

И реконсилер: при НЕДОСТУПНОЙ модели исполняем понятое шаблоном вместо `needs_review` с нулём
действий. Сегодня это не теория — с протухшим токеном каждое сообщение с недопонятой строкой не
сделало бы вообще ничего, включая перевод стопа в безубыток.
