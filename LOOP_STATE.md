# LOOP_STATE

## Goal: E2E-петля на своих каналах — я пишу пост, бот торгует на demo — ✅ ГОТОВО

Заказчик: «настрой e2e loop чтобы ты сам владел каналами, используемыми как override прод каналов,
отправлял туда посты в разных форматах и бот их обрабатывал и делал реальные сделки на демо…
настрой всю инфру для e2e и следующим этапом сформировать подробный план по тестированию всех
кейсов и прогнать», затем — «эти все моменты тоже пофикси» (все находки прогона).

## Этап 1 — инфраструктура: ✅

`apps/e2e` — отдельный workspace-пакет (тестовый код не течёт в прод-приложения), запуск из корня:
`pnpm e2e <команда>`. Документация — `docs/e2e/README.md`, каталог кейсов — `docs/e2e/test-plan.md`,
отчёты прогонов — `var/e2e/runs/*.{md,json}`.

| Команда | Назначение |
| --- | --- |
| `doctor` | 13 проверок готовности: контейнеры, **часы**, БД, сессия TG и права постинга, курсоры каналов, аккаунт Bybit, живой ответ модели, кэш инструментов |
| `reset` | Чистый лист: биржа в ноль + чистка следов тестовых каналов в БД + курсор на «сейчас» + тестовый профиль настроек |
| `run` | Прогон сценариев (`--only`, `--tag`, `--repeat N`, `--no-reset`, `--keep-open`) + отчёт |
| `session` | Отдельная сессия Telegram для постера (QR-обмен, авторизуется имеющейся сессией) |
| `post` / `trace` / `flatten` / `list` | Ручной пост, разбор последних сообщений, аварийное закрытие, список сценариев |

Сценарии — типизированный TS: шаг = пост (текст/фото/альбом/reply/правка/удаление) либо действие
оператора + ожидания по четырём срезам сразу (messages, actions, orders/trades/positions, **живая
биржа**). Цены строятся от живого mark price — иначе гейт slippage (0.5%) рубил бы вход.

**Важное открытие инфраструктуры:** постер и воркер не могут делить одну строку сессии Telegram —
воркер теряет realtime, и пост доезжает только бэкфиллом. Заведена отдельная сессия того же
аккаунта (`pnpm e2e session`, `E2E_TG_SESSION`); после этого шаг сценария подешевел с ~60 до ~5
секунд, а правка/удаление постов стали проверяемыми вообще.

## Этап 2 — каталог кейсов и прогон: ✅

16 сценариев / 45 шагов (`docs/e2e/test-plan.md`). Тексты предварительно прогнаны через адаптеры
офлайн — до траты живых ордеров поймано две ошибки формата (цели канала 2 требуют keycap-
разделителей `1️⃣…2️⃣…`; «свободный» вход со словом «стоп» уходит в детерминированное правило D).

Подтверждено ЖИВЫМИ ордерами на demo: вход + атомарный SL + TP-лесенка; SHORT; безубыток по
средней входа; «25% фиксирую» = ровно четверть; `symbol_busy`; `price_slippage`;
`invalid_sl_side`; отрицание «не фиксирую» не закрывает позицию; лимитка вне рынка; выключенный
тумблер копирования; ручное закрытие мимо бота; медиа и альбом; правка/удаление поста; весь путь
канала 2 — от структурного шаблона (без модели) до свободного текста и фиксации половины моделью.

## Этап 3 — исправление находок: ✅

Все четыре находки починены, каждая закрыта тестом. Тесты воркспейса: **772 зелёных**
(engine 481 из них), типы чистые по всем 7 пакетам.

**Финальная проверка живьём: два полных прохода подряд — 32 из 32 сценариев зелёные** (дефект
зеркала до фикса падал в 3 прогонах из 5), в логе движка ноль ложных предупреждений.

| Находка | Что сделано |
| --- | --- |
| 1. 🔴 Зеркало позиций залипало после полного закрытия (3 прогона из 5) | (а) водяной знак `bybit_seq` перенесён В САМ `UPDATE` WS-пути — конкурентные фреймы больше не затирают свежее состояние (lost update); (б) пайплайн сам прибирает за своим полным закрытием — зануляет зеркало и снимает остатки ордеров, **после коммита** (см. ниже про deadlock); (в) реконсиляция получила шаг Б2: гасит фантомные строки даже у ЗАКРЫТЫХ сделок (`phantomsZeroed`) |
| 2. 🔴 Исполнение своего ордера принималось за ручное действие (5+ раз за прогон) | `isEngineOrderLinkId()` — форма нашего ключа; эвристика «ручное» теперь работает только для ЧУЖОГО ключа; `applyExecutionPush` ждёт коммита своей строки `orders` перед атрибуцией (исполнение не ложится сиротой, PnL считается сразу) |
| 3. 🟠 `backfillAll()` мог залипнуть навсегда | Потолок на проход (`withDeadline`, 5 мин) — зависший вызов больше не держит single-flight-слот; тем же потолком накрыт ремонт медиа на старте |
| 4. 🟠 Дрейф часов Docker-VM ломал подпись (10002) | Часы биржи (`bybit/server-time.ts`): подпись REST и `expires` приватного WS считаются по времени БИРЖИ; синхронизация на старте, освежение по TTL и ПРИНУДИТЕЛЬНО по 10002 с повтором запроса |

### Что вскрылось уже в САМИХ фиксах (и тоже исправлено)

Прогон и адверсариальная проверка кода (10 агентов, 3 находки × 2 скептика + свод) поймали три
дефекта в первой редакции фиксов — все закрыты:

1. **`deadlock detected`** (поймал живой прогон). Зануление зеркала ВНУТРИ транзакции сообщения
   встречно блокировалось с транзакцией приватного WS: пайплайн держит `trades`/`symbol_ownership`
   и берёт `positions`, WS — наоборот. Postgres откатил сообщение целиком, притом что ордер на
   биржу уже ушёл (сценарий `ch2-market-flow` упал на «закрываю остаток» → `no_open_position`).
   Уборка вынесена **после коммита** (`finalizeClosedPositions`): одиночный UPDATE держит ровно
   одну блокировку и взаимно заблокироваться не может.
2. **Шаг Б2 не сработал бы в проде никогда** (поймала проверка кода). Его условие
   «зеркало старше снапшота биржи» опиралось на `positions.updated_at`, а тикер-фид бампал это
   поле на КАЖДЫЙ тик цены (~1/сек) для любой строки с size≠0 — фантом сам себя держал «свежим».
   Тик цены больше не трогает `updated_at`: это переоценка, а не изменение состояния.
3. **Побочные эффекты flat-пуша выполнялись, даже если UPSERT подавлен** водяным знаком: сделка
   закрывалась и с ЖИВОЙ позиции снималась защита по данным из прошлого. Теперь `RETURNING` —
   и `closeTrade`/`releaseSymbol`/`cancelAll` идут только если строка реально обновилась.

Плюс два сопутствующих дефекта, найденных проверкой:

- филл сработавшего НАШЕГО стопа приходит с ПУСТЫМ `orderLinkId`, и на WS-пути он тоже объявлялся
  «ручным действием» (`manual_override` на каждом срабатывании стопа). Теперь пустой ключ при
  активном владении символом атрибутируется как наш стоп (`stop_parent`), а не как вмешательство;
- после того как пайплайн стал занулять зеркало сам, хвостовой flat-пуш перестал атрибутироваться
  и КАЖДОЕ штатное закрытие писало в лог «владение символом не найдено». Предупреждение, горящее в
  нормальном потоке, обесценивается — добавлен фолбэк на НЕДАВНО закрытую сделку (окно 5 минут).
