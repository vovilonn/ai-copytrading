# LOOP_STATE

## Goal: «открой позицию с последнего скрина — бот проигнорил»

## Что было в канале

14.10 в 19:36–19:37 автор выложил ТРИ сообщения подряд:

| tg | что |
|---|---|
| 222042 | селфи-кружок (к торговле отношения не имеет) |
| 222043 | **скрин позиции: BTCUSDT Long 1.0 BTC @ 81 773.3, 20x, +0.70** — вход сделан минутой раньше |
| 222044 | «Папа вернулся 📈» |

Сам вход автор НЕ описал словами: позиция показана только картинкой.

## Почему бот промолчал — две независимые причины

1. **Картинка без подписи вообще не доходит до модели.** `ch2.adapter.ts::fallback` первой же
   строкой гасит пустой текст: `if (text.trim().length === 0) return noise` — route='noise',
   method=NULL, AI не вызывается. Весь vision-тракт (`needsVision`, картинки в контексте,
   `image_used`) при этом рабочий, но включается он только когда в тексте есть монета или торговый
   маркер. У медиа-онли сообщения текста нет — гейт не может сработать в принципе.
2. **Даже увидев скрин, модель считает его информационным.** Проверено живым вызовом
   extract_signal на этом самом сообщении: `message_type: "noise"`, confidence 0.95, резюме —
   «Screenshot of BTCUSDT long position status… No trading instruction given». То есть и после
   снятия гейта №1 этот вход бот бы не открыл: скрин позиции — это не приказ по нынешнему промпту.

Сообщение 222044 («Папа вернулся 📈») в модель ушло и честно классифицировано как болтовня —
картинка из 222043 в его контекст не попадает (разные сообщения, grouped_id пуст).

## Исполнено

| шаг | результат |
|---|---|
| вход по скрину | **доливка 0.008 BTC по рынку 81 917.8**, ордер `K02-222043-00-A0` filled |
| позиция BTC | была 0.016 @ 82 828.25 → стала **0.024 @ 82 522.53** |
| защитный стоп | пересчитан автоматически: 75 232.8 → **74 955.2** (та самая фича из прошлого loop, отработала в бою) |

Доставлено настоящим `processMessage` на самом сообщении-носителе 222043 (текст оператора
«Открыт лонг по битку с текущих» + его же картинка в контексте). Символ был занят TR-1133 —
пайплайн сам переклеил вход в `add` (`символ занят сделкой … → add`). В журнале: message
`executed · operator_open_from_screenshot`, у действия проставлен `detail` с происхождением.
