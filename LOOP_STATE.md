# LOOP_STATE

## Goal: «фикс половины SOL исполнен в убыток — проигнорирован контекст картинки автора»

Финансовая логика. Разбор по systematic-debugging: сначала корневая причина по фактам,
потом гейт, потом аудит соседних веток на тот же класс.

## Что произошло (msg 222501, TR-1136)

| когда (UTC) | событие |
|---|---|
| 24.10 23:38:28 | автор: «Половину фикс сол» + карточка результата |
| | карточка: **SOLUSDT Лонг 10X, +18.18%, цена открытия 100.66, последняя 102.49** |
| | наша позиция: 9.0 SOL, средняя **107.02** — то есть в МИНУСЕ при цене 102.5 |
| 24.10 23:38:40 | бот закрыл 3.1 SOL по 102.53: **exec_pnl −13.92 USDT**, комиссия 0.32 |

Модель картинку ПРОЧИТАЛА — `ai_summary`: «Partial close of 50% of SOLUSDT long position at
market. Image shows closed trade result card with +18.18% profit». И выписала `partial_close`
с confidence 0.98. Расхождение «у автора вход 100.66 / у нас 107.02» не заметил никто.

## Корневая причина

В `handleDelta` (pipeline.ts) гейт здравого смысла «фиксация прибыли при позиции В УБЫТКЕ»
стоит **только на ветке `tp_hit`**:

```
// Гейт здравого смысла: «цель взята» при позиции В УБЫТКЕ — противоречие.
if (!inProfit) { gateSkip = 'tp_not_reached'; break }
```

Ветка `partial_close` — та, в которую попадает «фикс половину», — исполняет закрытие
БЕЗУСЛОВНО. Разница между `tp_hit` и `partial_close` для автора чисто словесная («первая цель
есть» vs «половину фикс»), а для бота это разница между «спросил оператора» и «реализовал
убыток рынком».

## Фикс

Гейт переехал из ветки в общий предикат `positionPnlSign(position)` ('profit' | 'loss' | 'flat'
| null) и стоит теперь на ОБЕИХ денежных ветках:

| ветка | условие пропуска | причина в UI |
|---|---|---|
| `tp_hit` (закрывает треть сам) | `loss` или `flat` — цель не могла быть взята | `tp_not_reached` |
| `partial_close` («фикс половину») | `loss` — фиксировать в минус нечего | `fix_in_loss` |

Что гейтом НЕ закрыто и почему:

- `close_remainder` (полный выход) — исполняется всегда: вывести оператора из убытка канал
  должен мочь в любой момент. Спорна именно ЧАСТИЧНАЯ фиксация.
- цены нет (`mark_price = null`, dry-run без фида) — гейт не судит и пропускает команду:
  прямое указание автора не должно теряться из-за сбоя тикера. Так же ведёт себя `tp_hit`.
- `flat` (цена ровно на входе) для `partial_close` НЕ блокируется: убытка там нет.

Тест воспроизводит живой инцидент: позиция в минусе → `closePosition` не вызывается, действие
`skipped/fix_in_loss`, объём не тронут. До фикса падал ровно на `expect(calls).not.toContain
('closePosition')`. Движок: **712 зелёных**, `pnpm -r typecheck` чист.

## Аудит соседних веток на тот же класс («приказ по ЧУЖОМУ состоянию»)

| ветка | вердикт |
|---|---|
| `partial_close` | **был дефект — закрыт** |
| `tp_hit` | гейт был и раньше |
| `close_remainder` | сознательно без гейта (выход из убытка) |
| `sl_breakeven` | гейт `sl_beyond_market`: безубыток в минусе биржа и так отвергнет |
| `sl_set` ценой автора | гейт `stopLossReachable` (стоп по ту сторону рынка) |
| `sl_hit` / `tp_hit`-событие | ордеров не порождает |
| `cancel_pending` | отменяет НАШ неисполненный ордер — чужого состояния не касается |
| **`tp_set` (лесенка целей)** | **та же дыра, не закрыта — см. «Осталось» п.1** |

## Осталось (решает владелец)

1. **Цели автора ниже нашего входа.** `handleTpSet` сверяет цели только с РЫНКОМ (reduce-only
   лимитка по ту сторону рынка исполнилась бы мгновенно) — но не с нашей средней. По SOL сейчас
   вход 107.02, рынок 101.28: «следующие цели 103, 105» пройдут гейт и повесят reduce-only
   продажи, которые при срабатывании зафиксируют минус. Это тот же класс («цены автора
   отсчитаны от ЕГО входа»), и это ПОВЕДЕНЧЕСКОЕ решение, а не баг: блокировать такие цели —
   значит оставить позицию без плана выхода. Нужно слово владельца.
2. Чужой вход виден только модели. Карточка результата несёт «цену открытия» автора (100.66),
   и расхождение с нашей средней можно показывать оператору прямо в действии — но для этого
   модель должна её выдавать отдельным полем (бамп `PROMPT_VERSION`, нужны golden-тесты).
3. Живой e2e `apps/api/test/instruments.e2e.test.ts` красный НЕ из-за этого лупа: Bybit отдаёт
   по BTCUSDT `mmr = 0.0033`, в тесте зашито `0.005`. Число приходит с биржи и участвует в
   расчёте защитного стопа (`computeLeverage`) — надо решить, фиксировать ли его в тесте.

## Осталось от прошлых лупов (решает владелец)

4. Сигнал о неатрибутированной позиции не доходит до оператора (`audit_log` → никуда).
5. Модель противоречит себе на «тейк ‹цена›» с карточкой — нужна своя петля с golden-тестами.
6. Свободная маржа считается снапшотом раз в 30 с — прямой триггер 110007 на многомонетных.
7. `trades.size` не уменьшается при частичной фиксации (чинится реконсиляцией за 10 мин).
8. Двухмонетные строки в `ch2.adapter.ts`, привязка ключа Bybit к IP, ~12 старых `needs_review`.
