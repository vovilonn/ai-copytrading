# LOOP_STATE

## Goal: ожившая модель и дообработка всего, что зависло без неё

Заказчик: «сам вызови и скинь ссылку, я авторизуюсь, не хочу заходить на сервер».

## Авторизация без доступа к серверу

Прокси слушает только loopback сервера (`127.0.0.1:8317` — API и management, `127.0.0.1:54545` —
приёмник OAuth-колбэка), а `redirect_uri` жёстко ведёт на `localhost:54545`. Схема:

1. SSH-туннель с ноутбука: `15454 → сервер:54545`, `18317 → сервер:8317`.
2. Ссылка получена через management API сервера (`/v0/management/anthropic-auth-url?is_webui=1`).
3. Локально поднят приёмник на `:54545`, который проигрывает колбэк НА СЕРВЕРЕ. Это принципиально:
   на ноутбуке порт 8317 занят собственным прокси пользователя (`CLIProxyM`), и «родной» редирект
   отдал бы код авторизации не туда.
4. Колбэк заказчик прислал ссылкой — код проигран на сервер вручную, обмен прошёл на
   `127.0.0.1:8317/anthropic/callback` → «Authentication successful».

Проверено живым вызовом: `POST /v1/messages` → 200, модель ответила. Туннель и приёмник после
завершения сняты.

(сообщение, тип действия, символ) считал ступени лесенки дублями друг друга. Ключ дополнен ЦЕНОЙ

дублей, а разные уровни различимы.
