## 1. CHANNEL 1 (2088626562) — регулярный формат

Порядок применения правил (первый матч выигрывает):

**R1. ENTRY SIGNAL** (conf `0.6 + 0.1·|{sym,dir,entry,SL}|` → 1.0 при всех):
- гейт: `#([A-Z0-9]+)/USDT` **И** наличие `Диапазон входа`
- `sym` = `#(...)\/USDT` → `+USDT`
- `dir` = `📉|SHORT` → short, `📈|LONG` → long
- `entry` = `/Диапазон входа:\s*([0-9., ]+?)\s*[-–—]\s*([0-9., ]+?)\s*\$/`
- `tps` = из строки `/TP:\s*([^\n]+)/`, затем все `([0-9.,]+)\s*\$` (лесенка 1–3 цели)
- `sl` = `/SL:\s*([0-9.,]+)\s*\$/`; **если SL нет → route=SKIP `reason:no_SL`** (реш. #4)
- `risk` = `/Риск:\s*([0-9.,]+)\s*%/` (опц.)
- Проверено: 27/27 сигналов извлечены со всеми полями (2796→`LIT short entry=[1.5273,1.4735] tp=[1.4428,1.3926,1.2777] sl=1.7137 risk=2`; 2864→`PUMPFUN entry=[0.0014856,0.0014548]`; 2831→`ALICE entry=[0.0133,0.0139] risk=1`).

**R2. MULTI_MGMT** (conf 0.85): гейт `Менеджмент`; извлечь все строки `/#([A-Z0-9]+)\b\s*[-—:]\s*([^\n#]+)/` → `{sym, acts}`. Проверено: 2818→`[PENDLE:{tp_hit,sl_be}, AERO:{sl_be}, BB:{hold}]`; 2889→`[APT:{sl_hit}, MET:{fix,close}, TIA:{hold}]`.

**R3. DELTA (reply)** (conf 0.9): `replyToMsgId != null` **И** `#TICKER` (кроме `#BTC`) **И** action-lexicon. `sym` = первый тикер. Reply даёт линковку к сделке, но она избыточна: `sym` сам определяет позицию (изоляция «один символ — один канал»).

**R4. DELTA_STANDALONE** (conf 0.8, route DET если action конкретный, иначе NOISE как hold): `#TICKER + action` без reply (напр. 2841 `#BB … по стоп-лоссу` → `{sl_hit,close}`; 2843 `#DEXE прикрываю` → `{fix,close}`). Требует lookup открытой позиции по символу.

**R5. NOISE**: `#BTC\s*обзор | Анонс | созвон | zoom\.us | копитрейдинг | okx | рефом`.

## 3. Парсинг чисел (проверенные regex)

```js
// число с разделителем тысяч (обычный пробел U+0020, nbsp U+00A0, narrow U+202F) и десятичной . или ,
const NUM = /\d{1,3}(?:[\u0020\u00A0\u202F]\d{3})+(?:[.,]\d+)?|\d+(?:[.,]\d+)?/g;
const toNum = s => parseFloat(s.replace(/[\u0020\u00A0\u202F]/g,'').replace(',','.'));
// keycap-цели: "1️⃣80.82️⃣82.33️⃣84" -> [80.8,82.3,84]
const splitKeycaps = s => s.split(/[0-9]\uFE0F?\u20E3/).map(x=>x.trim()).filter(Boolean).map(toNum);
```
Доказано на реальных строках дампа: `0.51396$`→0.51396; `1.5273-1.4735`→[1.5273,1.4735]; `62 000$` (в CH1 разделитель = обычный `U+0020`, проверено байтово на msg 2799)→62000; `15.920`→15.92; `0.0014856`→0.0014856; `0.0728`→0.0728; `1.12-1.125`→[1.12,1.125]. Keycap-сплит верифицирован на всех 7 CH2-сигналах (`1️⃣742️⃣75.53️⃣77`→[74,75.5,77]; `1️⃣1.0752️⃣1.0953️⃣1.115`→[1.075,1.095,1.115]).

**Замечание [ВАЖНО]:** для `Entry price:` использовать точку как десятичную; запятую-как-десятичную из дампа не встречал (comma-decimal только в WEEX-картинках `+35,15%`, туда парсер не лезет). Нормализовать `ё↔е`/`э↔е` (см. §7, ошибки на `тэйк`/`объем`).

## 4. Определение направления (полный список маркеров из дампа)

- **long**: `📈`, `LONG`/`Long` (CH1/CH2-блок), `Лонг`/`Лонги`/`лонг`, `Relong`, `Перезахожу в Лонги`, `Повторный Лонг`, `Пробую … Лонг`.
- **short**: `📉`, `SHORT`/`Short`, `Шорт`/`шорт`.
- В CH2 дампе реальных шортов нет — все входы long; `шорт` встречается только в аналитике (`шортовом брейкере` 221349, `заманить в шорт` 221351) → **должно быть NOISE**.

**[КРИТИЧНЫЙ БАГ, найден и исправлен в прототипе]:** JS `\b` — ASCII-only и **не создаёт границу перед кириллицей**. `\bлонг`/`\bшорт`/`\bбит…` молча не матчатся после пробела (msg 221418, 221431, 221377 сначала уходили в NOISE). Решение: (1) `dirLoose()` без `\b`, вызывается **только** внутри веток, уже загейченных сильной фразой входа (иначе `шортовом` даст ложный short); (2) `coinsIn` — Unicode-границы: `/(?<![\p{L}\p{N}])(...)(?![\p{L}\p{N}])/giu`. После фикса аналитика с `битке`/`шортовом` осталась NOISE (0 ложных входов), а `Лонг битка` распозналось.

## 6. Матчинг дельт → позиции (подтверждено цифрами)

**CH1 — reply детерминирован.** 31 reply из 100 (69 без reply). Классификация цели reply:
- **30/31 указывают напрямую на SIGNAL** (`rootHops=0, root=SIGNAL`).
- **1/31** (`2807→2803`) указывает на другой обзор (review→review) — не дельта к сделке, а утренний тред; `#ONDO hold` внутри матчится по символу+стейту, не по reply.

## 10. Интерфейс адаптера (TypeScript) — новый канал без изменения ядра

```ts
type Side = 'long' | 'short';
type Route = 'execute' | 'ai' | 'skip' | 'noise';   // execute = детерминированно, ai = LLM+state

interface ParseContext {
  channelId: string;
  message: { id: number; text: string; date: string;
             replyToMsgId: number | null; groupedId: string | null;
             media: string | null; mediaFile: string | null };
  // разрешение символа + reply/state, ядро передаёт, адаптер не знает про Bybit:
  resolveSymbol(raw: string): string | null;         // алиас → BYBITSYMBOL (или null)
  isListed(symbol: string): boolean;                 // instruments-info кэш активной сети
  getMessage(id: number): ParseContext['message'] | null;   // для транзитивного reply-подъёма
  // state «один символ — один канал»:
  openPositions: ReadonlyMap<string, { tradeId: string; side: Side; openedByChannel: string }>;
  lastTouchedSymbol: string | null;                  // для символ-less дельт CH2
}

type ParsedIntent =
  | { kind: 'entry_signal'; symbol: string; side: Side; entry: [number, number] | number;
      tps: number[]; sl: number; riskPct?: number }                 // R1 / A
  | { kind: 'limit_entry';  symbol: string; side: Side; price: number }  // B
  | { kind: 'market_entry'; symbol: string; side: Side }                 // C
  | { kind: 'add';          symbol: string; price?: number }            // доливка (реш. #6)
  | { kind: 'delta'; symbol: string | null; ops: DeltaOp[]; targetTradeId?: string }; // R3/R4/D/E

type DeltaOp =
  | { op: 'tp_hit'; index?: number } | { op: 'partial_close'; fraction?: number }
  | { op: 'close_remainder' } | { op: 'sl_breakeven' } | { op: 'sl_hit' }
  | { op: 'sl_set'; price: number } | { op: 'sl_cancel' } | { op: 'hold' };

interface ParsedResult {
  route: Route;
  confidence: number;                 // [0,1]
  intents: ParsedIntent[];            // >1 при мульти-ордер/мульти-mgmt (E2/E4)
  reason?: string;                    // 'no_SL' | 'symbol_not_listed' | 'symbol_unknown_needs_vision'
  needsVision?: boolean;              // CH2: символ только в mediaFile
}

interface ChannelAdapter {
  readonly id: string;
  parse(ctx: ParseContext): ParsedResult;   // единственный контракт; ядро вызывает по channelId
}
```

**Что в `ctx`** (почему ядро не меняется при добавлении канала): резолв символа/листинга и весь state (`openPositions`, `lastTouchedSymbol`, `getMessage` для reply-подъёма) — в `ctx`, адаптер лишь извлекает интенты из текста. Роутинг/исполнение/AI-фолбэк/дедуп доливок — в ядре по `ParsedResult`. Новый канал = новый `ChannelAdapter` в реестре `Map<channelId, adapter>`; ядро, Bybit-слой и state не трогаются.
