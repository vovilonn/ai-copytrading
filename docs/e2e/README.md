# E2E-петля: я пишу пост — бот торгует на demo

Инструмент живёт в `apps/e2e`, запускается из корня: `pnpm e2e <команда>`.

Смысл: боевые каналы постят 2–8 сообщений в день, ждать живой сигнал ради проверки бота
бессмысленно. Поэтому источники подменены на **мои собственные каналы** (`TG_CHANNEL_OVERRIDES`), в
которые пишет тот же аккаунт-юзербот. Весь остальной путь — настоящий: Telegram → разбор → риск →
**реальный ордер на Bybit demo**.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm e2e doctor` | Проверяет готовность: контейнеры, часы, БД, сессия Telegram и права постинга, курсоры каналов, аккаунт Bybit, живой ответ ai-proxy, кэш инструментов. |
| `pnpm e2e reset` | Чистый лист: выравнивает биржу в ноль, стирает следы тестовых каналов из БД, двигает курсор бэкфилла на «сейчас», приводит настройки каналов к тестовому профилю. |
| `pnpm e2e run` | Прогон сценариев с отчётом (`--only id`, `--tag ch1`, `--no-reset`, `--keep-open`, `--repeat N` — повтор для ловли «плавающих» дефектов). |
| `pnpm e2e list` | Список сценариев. |
| `pnpm e2e post --ch 1 --text "…"` | Ручной пост (можно `--photo`, `--album a.jpg,b.jpg`, `--reply <id>`). |
| `pnpm e2e trace --ch 1 --last 5` | Что бот сделал с последними сообщениями канала. |
| `pnpm e2e flatten` | Аварийно закрыть всё на бирже. |
| `pnpm e2e session` | Завести постеру отдельную сессию Telegram (см. ниже). |

Отчёты прогона — `var/e2e/runs/<таймстамп>.{md,json}`.

## Обязательная деталь: отдельная сессия для постера

Постер и воркер tg-ingest не могут работать на **одной** строке сессии: Telegram отдаёт realtime
последнему подключившемуся, update-loop воркера уходит в цикл реконнектов, а `backfillAll()`
(single-flight) может «залипнуть» — пост тогда доезжает до БД только после перезапуска контейнера.

Лечится вторым auth-key **того же аккаунта**:

```bash
# 1) на аккаунте включён облачный пароль → положите его в .env
echo 'E2E_TG_2FA_PASSWORD=<облачный пароль>' >> .env
# 2) заводим сессию (тот же обмен, что вход по QR в Telegram Desktop: новый клиент просит
#    login-token, а уже авторизованная сессия TG_SESSION его принимает)
pnpm e2e session      # запишет E2E_TG_SESSION в .env
```

Без `E2E_TG_SESSION` петля всё равно работает: `doctor` предупредит, а раннер после каждого
«залипшего» поста сам перезапустит tg-ingest (+~40 секунд на шаг) и пометит это в отчёте. Но
проверяться при этом будет путь бэкфилла, а не realtime.

## Тестовый профиль каналов

`pnpm e2e reset` приводит настройки тестовых каналов к предсказуемому виду:

- `enabled = true` — иначе всё уходит в `skipped(copy_disabled)`;
- `trade_size = 150` USDT — фолбэк-нотионал для входов без риска в сигнале;
- `max_symbol_notional = 300` USDT — **важно**: сигнал с «риск 2%» при equity ~50k demo дал бы
  нотионал ~20 000 USDT (`risk × equity / стоп-дистанция`). Это штатная настройка канала, движок
  применяет её тем же кодом, что и в проде;
- `max_leverage = 10`, `no_sl_policy = attach_protective_sl`.

Значения переопределяются: `pnpm e2e reset --trade-size 200 --max-notional 500 --max-leverage 5`.

## Как добавить сценарий

`apps/e2e/src/scenarios/*.ts` — обычный TypeScript, ожидания типизированы:

```ts
export const myCase: Scenario = {
  id: 'ch1-my-case',
  title: 'Короткое описание',
  slot: 1,                       // 1 = структурный канал, 2 = свободный текст
  symbols: ['SOLUSDT'],
  steps: [
    {
      title: 'Что делаем',
      // текст — функция от живой цены: захардкоженная цена будет отбита гейтом slippage
      post: async (ctx) => ({ text: `Limit long sol ${await ctx.offset('SOLUSDT', -3)}` }),
      expect: {
        status: 'executed',
        actions: [{ type: 'open', status: 'executed', symbol: 'SOLUSDT' }],
        exchange: { symbol: 'SOLUSDT', position: 'flat', openOrdersMin: 1 },
      },
    },
  ],
}
```

Возможности шага: `post` (текст/фото/альбом/reply), `edit`, `deletePost`, `act` (вмешательство
оператора: `ctx.ops.setCopyEnabled`, `ctx.ops.closeOnExchange`), `expect.custom` — произвольная
проверка, возвращающая список расхождений. Новый сценарий нужно зарегистрировать в
`src/scenarios/index.ts`.

Каталог кейсов и что именно каждый ловит — [test-plan.md](./test-plan.md).
