# План e2e-тестирования: свои каналы → бот → реальные ордера на demo

Проверяем **весь путь целиком**: я публикую пост в свой Telegram-канал → tg-ingest сохраняет его →
engine разбирает (regex или модель) → риск/сайзинг → **настоящий ордер на Bybit demo** → зеркало
позиции и таблица действий в БД. Ни один шаг не подменяется моком.

- Каналы-источники подменены на мои: `TG_CHANNEL_OVERRIDES=1=3506730044,2=4322601605`
  (`bot_test_artemyev` → адаптер `ch1-structured`, `bot_test_aacademy` → `ch2-freeform`).
- Сеть — `demo` (реальные рыночные цены, виртуальный баланс), режим — `live`.
- Инструмент — **SOLUSDT**: цена ~$74, шаг лота 0.1 → нотионал ~$150–300 хорошо ложится и в
  минимальный лот, и в потолок `max_symbol_notional=300`, который e2e ставит тестовым каналам.

Запуск: `pnpm e2e doctor` → `pnpm e2e run`. Каждый сценарий начинается со сброса
(`биржа в ноль` + чистка следов тестового канала + курсор на «сейчас»), поэтому сценарии
независимы и их можно гонять по одному: `pnpm e2e run --only ch1-guards`.

## Что именно проверяет каждый сценарий

### Дымовой (без него остальное бессмысленно)

| # | Сценарий | Шаги | Что ловим |
|---|---|---|---|
| 1 | `smoke-ch1` | структурный сигнал → «зафиксировал 50%» ответом → «закрываю полностью» | Сама петля: пост юзербота доезжает до БД, движок его разбирает, ордер реально уходит на биржу, SL и TP-лесенка выставлены, частичное и полное закрытие двигают позицию. |

### Канал 1 — структурные сигналы (regex, `ch1.adapter.ts`)

| # | Сценарий | Кейсы | Правило адаптера / гейт движка |
|---|---|---|---|
| 2 | `ch1-short-be` | SHORT-вход; «стоп перевел в б/у» ответом; «Менеджмент → закрываю остаток» | R1 (side=short), R3 (delta-reply → `sl_breakeven`, безубыток = средняя входа), R2 (multi_mgmt). Отдельно проверяется, что недостижимый безубыток даёт `skipped(sl_beyond_market)`, а не падение сообщения. |
| 3 | `ch1-fraction` | вход; «Пробит хай, 25% фиксирую»; «фиксируюсь по текущим полностью» | Лексиконные фиксы (коммит `182a273`): доля читается из текста (**25%**, не дефолтные 50%), «полностью» — это `close_remainder`, а не половина. Сверяется фактический объём закрывающего ордера. |
| 4 | `ch1-busy` | вход; тот же сигнал повторно; закрытие | `symbol_ownership`: второй вход по занятому символу → `skipped(symbol_busy)`, позиция не удваивается. |
| 5 | `ch1-guards` | сигнал с ценой на −5% от рынка; LONG со стопом ВЫШЕ входа; сигнал по `#ZZZQQ/USDT` | Гейты `pipeline.ts` до открытия позиции: `price_slippage` (устаревший сигнал), `invalid_sl_side` (стоп по ту сторону), нерезолвящийся символ → уход в AI и **ноль ордеров** (вход, увиденный только моделью, не исполняется). |
| 6 | `ch1-noise` | «#BTC обзор…»; «анонс — созвон в zoom»; вход; «ничего пока **не** фиксирую»; «продолжаю удерживать»; закрытие | R5 (шумовые ключевики), R4 hold-only → noise, и главное — **отрицание**: до фикса лексикона «не фиксирую» закрывало половину позиции. Здесь это проверяется на живой позиции. |
| 7 | `ch1-media` | скрин графика с подписью-сигналом; альбом из двух картинок | Фолбэк → `route=ai` + `needs_vision` (модель смотрит график); альбом склеивается по `grouped_id` в один узел таймлайна. |

## Как формулируются ожидания

Каждый шаг сверяется по четырём срезам сразу:

1. **`messages`** — статус (`executed`/`skipped`/`needs_review`/`noise`), причина, метод разбора;
2. **`actions`** — тип, статус, символ, сторона, `skip_reason` по каждому действию;
3. **`orders`/`trades`/`positions`** — что записал движок (зеркало БД);
4. **живая биржа** — позиция, её стоп и живые ордера читаются с Bybit напрямую.

Ожидания на бирже проверяются в цикле до `settleMs` (25 с по умолчанию): ордер уходит синхронно
внутри обработки сообщения, а филл и позиция приезжают приватным WS чуть позже — одноразовая
проверка сразу после смены статуса флейкала бы на ровном месте.

Цены во ВСЕХ сценариях строятся от живого mark price (`ctx.offset('SOLUSDT', -0.1)`): вход всегда
рыночный, и гейт `MAX_ENTRY_SLIPPAGE_PCT=0.5%` зарубил бы любой сигнал с захардкоженной ценой.

## Что сознательно НЕ покрыто и почему

- **Срабатывание TP/SL по рынку.** Требует, чтобы рынок дошёл до цены — на demo это либо часы
  ожидания, либо цель вплотную к рынку (тогда тест проверяет случайность, а не логику).
- **TTL отмены лимитки** (`limit_ttl_sec` = 7 суток по умолчанию) — не влезает в прогон.
- **Реконсиляция после долгого даунтайма** (догон истории `executions`/`closed-pnl`) — нужен
  сценарий с остановкой движка на десятки минут; отдельная задача.
- **Мульти-символьные сообщения** («Перезахожу в лонги Sol Eth btc») — открывают 2–3 позиции за
  шаг; добавятся, когда будет решено, каким потолком экспозиции ограничивать прогон.
- **Второй канал как форум-топик** — оверрайд подставлен обычным каналом; ветка `topic_id`
  (`topic-filter.ts`) в этой конфигурации не задействована.
